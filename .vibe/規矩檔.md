# 規矩檔（AI 每次動工前必讀）

## 通用 AI 行為基準（從專案第一天起就成立，勿改）

1. **不准猜假設，不確定就問。** 收到任何指令，若有不明確的詞、有多種可能的解讀、缺少關鍵資訊——**停下來把不明確的地方列出來問使用者**，不要替他選一個解讀就動手。靜默的假設是這套系統最大的失敗源頭。

2. **每一行改動都必須能追溯到使用者的明確要求。** 不准順手「改進」相鄰的程式碼、不准重整不相干的格式、不准刪掉「看起來像死碼」但不在這次任務範圍內的東西、不准做沒被要求的重構。每一行 diff 都要對得上一句使用者講過的話。
   - **（刻意反「童子軍原則」，重要）**：工程界有條「童子軍原則／破窗效應」——路過爛 code 順手修乾淨。**這套系統故意不這樣做**：對看不懂程式碼的人，「順手清理」是**驗不到的暗改**，一個 drive-by「整理」可能靜默弄壞別處而他永遠看不到。所以**破窗要修，但要用一片正式的 `vibe-simplify`（走過審核）去修，不准路過時即興順手改**。清理是一個被切出來、驗得到的動作，不是夾帶在別的任務裡的副作用。

3. **不准加沒被要求的功能、抽象、設定項。** 「想說以後可能會用到」「順便寫得更彈性一點」「加個 config 比較好」——全部不准。要做的事跟使用者要的事一對一，多的一律砍。（注意：這條禁的是替想像情況**鍍金**；下面第 4 條的健壯性地板是**最低要求**，不在此限。）

4. **錯誤要大聲、輸入要驗、爆了要倒向安全側（健壯性地板）。** AI 寫的程式表面會跑，但**邊界與錯誤處理常常是空的**——而看不懂程式碼的人看不到空的 catch、看不到沒驗證的輸入。這四條是地板，寫任何程式一律遵守（這不是第 3 條禁的「鍍金」：錯誤一定會發生，差別只在「大聲報」還是「默默吞」）：
   - **快速失敗、不准默默吞**：一發現不對就大聲報錯停下，**不准用空的 catch 把錯誤吃掉繼續跑**。吞掉的錯不會消失，只會用更難懂的形式在更遠的地方爆。
   - **外部進來的一律先驗證**：使用者輸入、API 回傳、檔案內容——用之前先檢查，絕不假設它是好的（這同時是健壯性與安全的根）。
   - **爆掉時倒向「拒絕／鎖住」，不是「放行」**：尤其權限／付費／安全相關，出錯的預設是「不准」，不是「那就讓他過吧」。
   - **保護式子句**：不合法的狀況在函式開頭就擋掉提早 return，讓正常路徑保持平坦，不要把主邏輯埋在層層巢狀 if 裡。

## 專案特定規矩（vibe-voice-lock 之後寫入這下面）

（2026-11-16 立）

這一區管 AI 的判斷。用文字比對抓得到的規則由存檔前檢查 `.vibe/git-hooks/pre-commit` 擋，這裡不重複：Core 不准 import 畫面框架、不准留記錄輸出、不准空的 catch、畫面檔不准寫色碼、不准手改 DomyTokens、不准加第三方套件、不准加 ATS 例外、不准把「買了沒」存檔、不准放金鑰。

**先讀再寫**

- 動工前先讀要改的檔和它旁邊的檔，照既有的寫法寫，不自帶一套。
- 這台電腦不能編譯 Swift，寫錯要推上雲端才知道。沒把握的 API 先查 Apple 文件，不憑印象寫。

**東西放哪裡**

- 不靠 iPhone 就能算的判斷（主事件、版面、類別、農曆、付費內容能不能用）放 `Core/`，每條新規則配單元測試。
- 「有沒有買」只由 `PurchaseStore` 算。「能不能用」只在 `Core` 的一個檔判斷（現在是 `ThemeAccess.swift`）。畫面和其他 store 只問結果，不自己判斷。
- 新功能預設寫進現有的檔案與型別。要開新檔、拆新型別、加新的 store 之前先問使用者。

**不准引入的寫法**

- 不准加架構模式：Coordinator、VIPER、Repository、Service 層、依賴注入容器。現在是 `@Observable` 的 store 加 SwiftUI 畫面，照這個寫。
- 不准為只有一個實作的型別抽 protocol。不准用 associatedtype 或泛型去包只有一種用法的東西。
- 不准用 Combine。`async` 只用在真的要等的事（StoreKit、行事曆權限、`Task.sleep`）。
- `try?` 只准用在失敗也沒差的等待（`Task.sleep`）。其他會失敗的事用 do-catch，並把錯誤顯示在畫面上。

**可讀性**

- 名字要看得出用途：`previewThemeID` 可以，`tmp`、`flag`、`d` 不行。
- 註解用繁體中文，只寫為什麼（取捨、踩過的雷），不寫這一行在做什麼。
- 數字要有名字。設計系統有的用 `DT.*`；月曆格子專用的放 `Theme.Grid`；引導的放 `CoachStyle`；付費的上限放 `Core`。
- 函式只做名字說的事。名字叫「讀」的不准順手寫入或刪除。

**畫面**

- 顏色從 `Theme.*` 拿。文字的字級用 `dFont(DT.TypeScale.*)`，格子裡的小字用 `sFont`。SF Symbols 圖示的大小照現有寫法 `.font(.system(size:weight:))`。
- 可以點的東西至少 `DT.Size.touch`（44）。自己畫的按鈕要有 `accessibilityLabel`。
- 畫面上的字用繁體中文、台灣用語。同一個東西只有一個名字，取新名字前先查 `docs/SPEC.md` 有沒有舊的。

**不確定時**：選程式最少、最像旁邊檔案的做法，然後問使用者。
