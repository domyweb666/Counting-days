**判定證據**：

- 沒有第三方套件，只有自己的 `Core`

## 必查清單

每一組先列標準裡的檢查項，再寫蒜日子怎麼套。

### 1. 本機資料儲存（MASVS-STORAGE）

被打中會怎樣：拿到手機或備份檔的人，能直接讀到、改到 app 存的東西。

- [ ] 機敏資料不存在本機
- [ ] 必須本機存的機敏資料用 Keychain，不放 UserDefaults 明文、純文字檔、沒加密的資料庫
- [ ] 機敏資料不寫進記錄輸出（`print`、`NSLog`、`Logger`）
- [ ] 機敏資料不放進網址
- [ ] 敏感畫面防截圖
- [ ] 退到背景時遮蔽機敏內容

蒜日子怎麼套：

- UserDefaults 只放顯示設定：類別、置頂、短名、倒數日、主題。這些不是機敏資料，可以放。第 62 片起同一份設定多寫一份到跟小工具共用的 App Group（`group.com.domyweb.countingdays`），內容一樣，只有蒜日子與它的小工具打得開。
- 「買了沒」不准存進 UserDefaults 或任何自己的檔案。每次都從 StoreKit 已驗證的交易算出來。存了就等於讓人改一個值就免費用。
- 行程的標題、地點、備註不准寫進記錄輸出。目前程式裡沒有任何記錄輸出，之後加的話只能印「有幾筆」這種數字。
- 防截圖、背景遮蔽：不適用。app 沒有付款畫面（付款畫面是 Apple 的），行程內容跟系統行事曆一樣是使用者自己的資料。

### 2. 加密（MASVS-CRYPTO）

被打中會怎樣：自己寫的加密或驗證有洞，等於沒鎖。

- [ ] 不用過時演算法（MD5、SHA-1、DES、RC4）
- [ ] 用平台原生的加密 API
- [ ] 金鑰放 Keychain，不寫死在程式裡
- [ ] 隨機數用安全的來源

蒜日子怎麼套：

- app 自己不做任何加密。
- 內購的交易驗證用 StoreKit 2 給的結果，只接受「已驗證」，不自己解析、不自己驗簽章。
- 程式裡不准出現任何金鑰、密碼、權杖。上傳 TestFlight 用的金鑰只放 GitHub Secrets。

### 3. 網路通訊（MASVS-NETWORK）

被打中會怎樣：同一個 Wi-Fi 上的人能看到或竄改 app 傳的資料。

- [ ] 所有連線強制 HTTPS
- [ ] 啟用 ATS，不加例外
- [ ] 處理金錢、醫療的 app 做憑證綁定
- [ ] 不忽略憑證錯誤

蒜日子怎麼套：

- 目前 app 自己不連網，內購的連線由 Apple 的 StoreKit 處理。
- `Info.plist` 不准加任何 ATS 例外。
- 天氣那幾片開始連網時用 Apple 的 WeatherKit，不自己接第三方天氣服務。如果哪天要接，只能走 HTTPS，回來的資料用之前先檢查格式。
- 憑證綁定：不適用。app 不經手金流，付款全程在 Apple 那邊。

### 4. 驗證與授權（MASVS-AUTH）

被打中會怎樣：別人能冒用使用者的身分，或沒付錢的人用到付費功能。

- [ ] 登入用標準協定，不自己發明
- [ ] 權杖放 Keychain
- [ ] 敏感操作要再次確認身分
- [ ] 登出時清掉本機權杖
- [ ] 更新權杖的機制不由 app 端自己決定

蒜日子怎麼套：

- 沒有帳號、沒有登入，登入相關的項目不適用。
- 「有沒有買」就是這個 app 唯一的授權判斷，規矩如下：
  - 驗不出來、查詢失敗、還在載入，一律當成沒買。
  - 退款或被撤銷之後重新鎖上。
  - 判斷只寫在一個地方，所有要看「有沒有買」的畫面都問那一個地方，不各自判斷。
  - 試看只改畫面，不寫進設定檔。離開試看時沒買就換回去；app 在試看中被滑掉，重開也要是沒買的樣子。
  - 價格只顯示 App Store 回傳的，程式裡不寫數字。

### 5. 平台互動（MASVS-PLATFORM）

被打中會怎樣：別的 app 或一條連結能叫蒜日子做事。

- [ ] WebView 關掉不必要的功能，不直接暴露原生功能
- [ ] 處理外部連結時檢查來源
- [ ] 跟其他 app 互通的入口有來源檢查
- [ ] 不對外開放不該被呼叫的元件

蒜日子怎麼套：

- 目前沒有 WebView、沒有分享擴充。有小工具（第 60 片起）、控制中心的「新增行程」按鈕（2026-11-26），和兩個自訂連結 `suanrizi://today`（第 65 片）、`suanrizi://new`（2026-11-26），都不帶參數，跟這兩串不完全一樣的一律忽略（`WidgetLink`，有單元測試）。控制中心按鈕不走連結，是蒜日子裡的動作發通知給 `AppModel`，只在蒜日子自己的程式裡傳。
- 之後連結要帶參數（日期、行程編號）時，要先檢查，不合法就忽略。

### 6. 程式碼品質（MASVS-CODE）

被打中會怎樣：用到有已知漏洞的舊版本或來路不明的套件。

- [ ] 用還在維護的 SDK 版本
- [ ] 第三方套件從官方來源取得
- [ ] 第三方套件鎖定版本
- [ ] 開啟編譯器的安全選項

蒜日子怎麼套：

- 雲端建置固定用 Xcode 26。
- 目前沒有任何第三方套件。要加之前先問使用者，加了要鎖版本。
- 外部進來的資料（系統行事曆的內容、設定檔、之後的天氣資料）用之前先檢查。設定檔讀不回來時用預設值並把壞掉那份留著，這條已經有了。

### 7. 抗逆向工程（MASVS-RESILIENCE）

被打中會怎樣：有人改 app 或用越獄手機繞過付費。

- [ ] 偵測越獄
- [ ] 程式碼混淆
- [ ] 偵測除錯工具
- [ ] 檢查 app 有沒有被改過

蒜日子怎麼套：

- 整組不做。賣的是配色，被繞過的損失很小，而這些偵測常常誤傷正常使用者。
- 使用者要知道的代價：越獄手機上的人有辦法不付錢用到付費主題。

### 8. 隱私（MASVS-PRIVACY）

被打中會怎樣：上架被退件，或使用者發現 app 做了沒講的事。

- [ ] 每個權限都有正當理由
- [ ] 蒐集了什麼要告知使用者（隱私權宣告檔）
- [ ] 提供刪除資料的方法
- [ ] 第三方套件蒐集了什麼要告知

蒜日子怎麼套：

- 只要行事曆一個權限。不准為了方便多要定位、通訊錄、通知。天氣用設定裡選的縣市，不要定位，這是已經定下來的。
- `App/PrivacyInfo.xcprivacy` 目前宣告：不追蹤、不蒐集、有用 UserDefaults（自己的那份 CA92.1；第 62 片起多一份放在跟小工具共用的 App Group，1C8F.1）。小工具從第 63 片開始讀那一份，有自己的隱私清單 `Widget/PrivacyInfo.xcprivacy`（1C8F.1）。每加一個功能要回頭看這份還對不對。
- 權限頁與「關於」寫著「沒有帳號，也沒有伺服器」。加內購那一片要補一句購買由 Apple 處理；天氣開始連網那一片要改寫。畫面上講的要跟 app 做的一致。
- 刪除資料：app 的設定刪掉 app 就沒了，行程在系統行事曆裡，由使用者自己管。

## 上線前流程

使用者說「準備上架」「跑安全檢查」時：

1. 觸發 `vibe-security-gate` 階段 C
2. AI 對著這份逐項檢查現有程式
3. 產出 `.vibe/安全檢查報告.md`
4. 沒有嚴重問題才可以上架，有就必修

## 這份做不到的事

- 不能取代專業的安全測試。
- 看不出設計上的漏洞，例如試看的流程有沒有哪一條路能把付費主題留下來。這種要靠逐條走流程來驗。
- 內購的付款流程在模擬器上測不到，要用 TestFlight 加沙盒帳號在手機上驗。
