# 蒜日子 規格

版本：2026-11-14 初版。對應 `design/` 裡的六張畫板。

## 1. 這個 app 是什麼

一個只做「看」的月曆：把 iPhone 系統行事曆裡的事件，用手機上看得清楚的方式顯示。核心動作是「打開，一眼看出接下來哪幾天有事、是什麼事」。

不做的事：自己的帳號系統、自己的雲端同步、待辦清單管理、週檢視與日檢視的完整時間軸。

## 2. 平台與技術

- iOS 原生，SwiftUI。最低版本 iOS 17（EventKit 的完整取用權限 API 從這版開始）。
- 開發機是 Windows、沒有 Mac，建置與簽章走雲端（GitHub Actions 的 macOS runner）。
- 介面語言：繁體中文。

## 3. 資料

### 3.1 系統行事曆是唯一的資料來源

- 用 EventKit 讀寫。使用者在 iPhone「設定」加過的 iCloud、Google 等帳號的行事曆都會出現，不需要另外串任何帳號。
- 不複製事件到自己的資料庫。每次顯示都從 EventKit 查當前可見範圍（當月前後各一個月）。
- 監聽 `EKEventStoreChanged`，系統行事曆一有變動就重新查詢。
- 新增、修改、刪除事件直接寫回 EventKit。第一版可以用系統內建的事件編輯畫面（`EKEventEditViewController`）。

### 3.2 權限

- 第一次打開先顯示一頁說明（為什麼需要、資料不會離開手機），再呼叫 `requestFullAccessToEvents`。
- `Info.plist` 要有 `NSCalendarsFullAccessUsageDescription`。
- 被拒絕時顯示空狀態，說明要到「設定」開啟，並提供跳轉按鈕。

### 3.3 app 自己存的資料（只存系統行事曆沒有的）

存在本機（SwiftData 或 UserDefaults），以事件識別碼或行事曆識別碼為鍵：

| 資料 | 說明 |
|---|---|
| 置頂 | 某事件被使用者標為當天主事件 |
| 短名 | 某事件在月檢視格子裡顯示的短標題 |
| 行事曆對類別 | 每一本行事曆屬於哪個類別 |
| 關鍵字規則 | 標題含某些字就歸某類別（補強用） |
| 節日行事曆 | 哪幾本行事曆被當成節日層 |
| 呈現方式 | 使用者上次選的 A／B／C／D |

重複事件的置頂與短名以整個系列為單位。

## 4. 資訊層級

由強到弱，月檢視的所有呈現方式都遵守：

1. **跨日事件**：整條色帶，最大的字。
2. **當天主事件**：每天只有一件，實色塊加文字。
3. **其餘事件**：不寫字，每件一個 8 px 小色塊，顏色是類別。最多 4 個，再多在後面加「+」。
4. **節日**：背景層，見第 8 節。
5. **每天重複的例行事件**：月檢視不顯示，只在點開當天時出現。

### 4.1 主事件怎麼選

依序比較，分出高下就停：

1. 使用者置頂的。
2. 有地點、有受邀者或屬於「看診」「行程」類別的。
3. 一次性事件優先於重複事件。
4. 當天開始時間最早的。

### 4.2 格子裡的文字

- 一行最多 3 個全形字，最多兩行，所以 6 個字以內完整顯示。
- 超過 6 個字：有短名用短名；沒有就取標題前 6 個字。
- 完整標題只在點開當天的時間表裡顯示。

### 4.3 時間狀態

- 今天以前的事件：灰底灰字（`#E3E6EB` 底、`#454C57` 字），小色塊也變灰。
- 今天：日期數字是黑底白字的圓。
- 完全過去的週：收成一行，只剩日期數字與類別色點。

## 5. 類別與顏色

| 類別 | 顏色 | 用途 |
|---|---|---|
| 工作 | `#6D28D9` | 會議、錄影、交稿 |
| 行程 | `#1D4ED8` | 旅行、聚餐、有約 |
| 看診 | `#C2410C` | 醫療相關 |
| 辦事 | `#0F766E` | 領件、跑腿、填表 |

- 實色塊上的字一律白色，四個顏色對白字的對比都超過 4.5:1。
- 類別預設由「行事曆對類別」決定；關鍵字規則可以覆蓋。沒有對應的行事曆歸「行程」。
- 類別的名稱與數量要能在設定裡改。上表是預設值。

其他顏色：底色 `#F4F5F7`、卡片 `#FFFFFF`、主要文字 `#14171C`、次要文字 `#5B6370`、選取外框 `#1D4ED8`、跨日事件的附屬資訊底 `#DBE5FF` 配字 `#1E3A8A`。

字體用系統字體。字級：月份標題 34、時間表主事件 19、色帶標題 16–17、日期數字 15、格內文字 13–14、輔助說明 12。所有可點的東西至少 44 pt。

## 6. 四種呈現方式

標題下方一排四顆切換鈕，四種方式吃同一份資料，切換時保留選取的日期。

### A 彈性週（預設）

- 7 欄月曆，星期對齊。
- 當天所有事件都用色塊加文字列出，那一週跟著長高。
- 沒有事件也沒有跨日事件的週，壓成 40 pt 高的一行。
- 跨日事件是橫跨欄位的色帶，在該週的日期列下方；跨週時左右兩端的圓角只留在真正的起訖端。

### B 清單

- 上面是小月曆，只有色塊沒有文字：有事的日子整格塗主事件的類別色，跨日事件是連續色帶，今天是黑框圓。
- 下面是「接下來」清單，從今天起每個有事的日子一張卡：左邊日期色塊，中間主事件大字，下一行「還有 ○○、○○」，右邊「N 天後」。
- 跨日事件在開始日出現一張卡，寫起訖與總天數。

### C 週條

- 一週一橫條，欄位不對齊。
- 沒事的日子縮成 30 pt 寬的窄條（日期加星期）。
- 有事的日子撐開成卡片，列出當天所有事件的完整標題，主事件字最大。
- 跨日事件在該週合併成一整塊。
- 一週有 4 天以上有事時，卡片改成精簡版：日期、主事件短名、小色塊。
- 整週沒事時，是一行 7 個等寬的日期。

### D 主事件

- 版面同 A，但每天只顯示主事件一個色塊，其餘事件是小色塊。
- 適合每天事件很多的人。

## 7. 點一天展開

- 四種方式點任何一天，都展開成同一種時間表面板。再點同一天或按面板的關閉鍵收合。
- 面板位置：A、C、D 在該週正下方；B 在小月曆與「接下來」之間。
- 面板內容：標題是「11/16 週一」與件數；每件事一列，依時間排序，有時間、類別色塊、完整標題；主事件那列是整條實色、字最大。
- 當天在跨日事件範圍內時，最上面多一列「全天 · ○○ · 第 N 天」。
- 沒事的日子顯示「這天沒有行程」。
- 被選的日期有藍色外框。
- 「今天」按鈕會捲到今天並展開今天。
- 面板裡點某一件事，開啟系統的事件編輯畫面；長按可以置頂或設定短名。

## 8. 節日層

- 節日不是事件：不佔主事件位置，不算進小色塊。
- 顯示方式：節日那天的日期數字變色，下方一行 11 pt 小字寫節日名稱（最多 3 個字）。
- 資料來源：系統裡被標為節日的行事曆。第一次啟動時，自動把訂閱類型且名稱含「節日」或「Holidays」的行事曆設為節日層，使用者可以在設定裡改。
- 節日行事曆裡的事件，一律走節日層，不走第 4 節的規則。
- 補班日與補假：內建節日行事曆的涵蓋情況未查證。若不足，第二版接政府公開的辦公日曆表。

## 9. 邊界情況

| 情況 | 處理 |
|---|---|
| 整個月每天都有事 | 月曆可上下捲動；過去的週一律收成一行 |
| 兩個跨日事件重疊 | 最多疊兩條色帶，第三條以後縮成 4 pt 細線 |
| 一天超過 5 件事 | 小色塊最多 4 個加「+」；A 方式最多列 5 件，其餘寫「還有 N 件」 |
| 全天的單日事件 | 當成一般事件，時間欄寫「全天」，參與主事件比較 |
| 標題是英文或很長 | 格內依寬度換行，最多兩行，超出用短名或截斷 |
| 沒有任何行事曆權限 | 空狀態加前往設定的按鈕 |
| 跨月 | 月曆是連續的週，不在月份邊界切斷；標題顯示目前畫面佔最多天數的月份 |

## 11. 還沒決定的事

1. 類別由「行事曆」決定是否符合實際使用習慣。目前的行事曆事件多半在同一本裡，照這個規則會全部同色，需要搭配關鍵字規則或把行事曆分開。
2. 主事件的比較順序是否要讓使用者自訂（例如工作永遠優先）。
3. 是否上架 App Store，或只自用。
